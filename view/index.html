Reference Guide

What you are looking at

One sampled completion at a time. A run is a directory under runs/. Each run saves every completion it samples, one file per split and training step.

train
The completions sampled for the optimizer step with that number. Step 0 is the untouched base model.
eval
The fixed held-out problems, sampled again at that step. Compare the same problems across steps here.
baseline
Base-model samples from baseline.py, with no training.

Outcome

Correct
The parsed answer matches. Reward 1.
Wrong
An answer was given in the required format but it is wrong. Reward 0.
No answer
No answer in the required format (missing tags, cut off at the token limit, text after the answer line). Reward 0.

Group

The row of squares shows every completion sampled for the same prompt in this file, colored by outcome. GRPO scores each one against the others in its group. Click a square to jump to it; faded squares are hidden by the current filters.

Reasoning and answer

The completion is split for display only: the reasoning is everything before </think> (tags format) or before the last line (plain format), and the answer is shown without its tags or "Answer:" label. Tick "Raw" (or press r) to see the completion exactly as sampled. Reward never looks at the reasoning.

Shaded characters are non-ASCII: other scripts, unusual symbols. Turn on "Show whitespace" to see newlines and repeated spaces.

Across steps

Tick "Across steps" (or press c) to follow one prompt through training: every completion sampled for it in every file of the same split, in step order, with outcome, parsed answer and reasoning length. Held-out (eval) prompts recur at every eval step, so use an eval file. Training prompts are drawn fresh and appear at one step only.

Keys

← / → (and the arrow buttons): previous / next prompt
j / k: previous / next completion
[ / ]: previous / next file (step)
g: next completion in the same group
c: toggle across steps
r: toggle raw completion
